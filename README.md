# 锁屏快捷台 · LockDeck

> 安卓控制中心里的天气读数 + 两个可自定义的快捷动作按钮。

一个很小、很个人的工具 App：把「下拉看一眼现在几度」和「点一下就扫码/付款」放进系统控制中心，不用先解锁、不用先找 App。

代码里那些长注释不是写给编译器看的，是写给下一个改它的人看的——**每一条都对应一次真机踩坑**，包括哪些路试过、为什么放弃。

## 它做什么

**控制中心四个格子**

| 按钮 | 功能 |
|---|---|
| 天气 | 当前温度，**纯数字**、大号铺满一格（不画「°」，去掉之后字号还能再大一截）。**点一下刷新** |
| 今日高低温 | 上面最高、下面最低，两个数字各占半格。**点一下刷新** |
| 快捷按钮 ① | 自己选：支付宝扫一扫 / 微信扫一扫 / 收付款 / 任意 App / 刷新天气 |
| 快捷按钮 ② | 同上，默认微信扫一扫 |

天气为什么要占两格：一个格子的图标区被系统钉死在 96×96px（见「已知限制」），
「当前温度 + 最高 + 最低」三样塞进去，底下那行只剩约 11px 高，一瞥根本读不出来。
拆成两格之后，当前温度能铺满整格，高低温各自占半格——**用一格位置换「看得清」**。
高低温只靠**位置 + 亮度**区分（上高下低、上面更亮）：系统会把图标整体染白，
但 alpha 保留，所以「暗一档」画得出来。试过加箭头，实测它占掉横向三分之一、
把数字挤小，最后删了——控制中心里**大就是清楚**，符号是在跟数字抢注意力。

按钮一进来是空的——控制中心放哪些格子只有用户自己能决定，App 只能「请求添加」，最终要你在「编辑」里把按钮拖上去。

**通知栏常驻天气**

一行系统原生样式通知：温度、今日高低温、体感/湿度/紫外线/风、空气质量、下一场雨。点它执行你绑定的动作。

**「下一场雨」怎么说**

分两级，因为两件事的可信度完全不同：

| 时间跨度 | 来源 | 例子 | 能不能拿来做决定 |
|---|---|---|---|
| 2 小时内 | 雷达外推，逐分钟 | 「约 25 分钟后下雨」 | 能。这就是「现在出不出门」 |
| 2 小时以外 | 模式预报，整点 | 「明天 2 点前后有雨」 | 参考。别拿它当闹钟 |

有雨时它顶到通知标题（`明天 2 点前后有雨` / `正在下雨`），没雨时通知还是原来那两行，不多占地方。

时间点一律带「今天 / 明天」，**不写「凌晨 2 点」**：晚上 11 点看到「2 点有雨」分不清是凌晨还是下午。判断按日历天算，不按「几小时后」——23:50 说的「明天 2 点」和次日 01:00 说的「今天 2 点」是同一个时刻。

**锁屏下点按钮不会被拦**

锁屏上直接 `startActivity` 会被系统挂起，用户得自己上滑解锁才看得到，表现就是「点了没反应」。这里走一层透明中间页主动请求解锁，验证通过后自动续跳——感知上就是「点了就进」。

## 天气数据从哪来

三个源，设置页自己切，**不做静默降级**（静默降级只会让人看到「温度忽然变了两度却不知道为什么」，比直接报错更难查）：

| 源 | 说明 |
|---|---|
| **小米天气**（默认） | 私有接口，数值和手机自带天气完全一致——本来就是同一个后端，还带分钟级降水与空气质量。没有文档、没有 SLA，哪天改了校验就失效 |
| **中央气象台** | `weather.cma.cn` 观测站，免费、无需 key、最稳。但按气象站给数据，市区几个区可能共用同一个站，实况和手机差 2 度上下 |
| **Open-Meteo** | 免费开源、有 SLA，最后一道防线。显式指定中国 CMA 模式，但仍是格点插值不是观测 |

### 降水那三个数字，其实来自三个地方

这是这块最容易搞错的地方，分开说：

| 显示 | 接口 | 更新频次 | 可信度 |
|---|---|---|---|
| 「约 25 分钟后下雨」 | `/weather/xm/forecast/minutely`（**独立接口**） | 约 1 分钟 | 雷达外推，2 小时内很准 |
| 「明天 2 点前后有雨」 | `/weather/all` 的 `forecastHourly.weather` 里的降水时次 | 5 分钟 | 模式预报，只到整点 |
| 「今日降水概率 60%」 | `forecastDaily.precipitationProbability` | 5 分钟 | 彩云给的日概率，**只当参考** |

最后那个有坑：实测长沙报「小雨」、这一列给 0；香港报 69% 却只是多云。它是另一家数据商算的，别拿它判断「今天下不下」。App 里也一样，`0%` 根本不显示——一片 0 既没信息量又占地方。

小米那条的 `appKey` / `sign` 是从 [Breezy Weather](https://github.com/breezy-weather/breezy-weather)（LGPL-3.0）照抄的公开常量，不是本项目的资产。**用私有接口是有代价的**：它对我们是敞开的，也随时可能关上门。实测 `sign` 只校验非空、不校验内容（填 `WRONGSIGN123` 照样返回数据），所以它现在对我们敞得挺开——也正因如此，哪天它开始真校验，我们会立刻失效。

分钟级降水那个接口还要求 `locationKey`（缺了直接 400），但它**同样不校验内容**：填别的城市、甚至假 key，返回的仍是按 `lat/lon` 算的那份。所以取不到 key 时兜一个默认值就行，别为了这一步丢掉整个降水预报。

定位拿不到就显示「等待定位」，**绝不编一个坐标顶上**——老版本干过这事，用户明明在 A 城却看到 B 城天气，界面上一点异常都没有。

## 构建

需要 JDK 17+ 和 Android SDK（`compileSdk = 37`）。

```sh
git clone https://github.com/JackAIStudio/LockDeck.git
cd LockDeck
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`local.properties`（里面只有 `sdk.dir`）不入库，Android Studio 打开会自动生成；命令行构建请自己写一行，或设 `ANDROID_HOME`。

| 组件 | 版本 |
|---|---|
| Kotlin | 2.3.20 |
| AGP | 9.0.1 |
| Gradle | 9.1.0 |
| Compose BOM | 2026.03.01 |
| minSdk / targetSdk | 31 (Android 12) / 37 |

## 已知限制

这些不是 TODO，是**已经查清的边界**，写下来省得后来者重跑一遍：

- **只在 HyperOS 3（Redmi Turbo 5 / Android 16）上做过真机验证。** 原生 Android 上照样能跑，但下面第一条和第三条限制只针对 HyperOS（第二条里 WorkManager 的问题在原生 ROM 上反而不存在，所以它留着当兜底）。
- **通知上不了锁屏。** HyperOS 的锁屏通知由 SystemUI 的 `KeyguardCoordinator` + `MiuiNotifCoordinator` 判定，第三方应用默认被判 `keyguard=false`。importance、静音、勿扰、焦点通知/超级岛都逐一排除过，全都不是原因——闸门是 MIUI 按应用下发的权限，App 侧无法用参数绕过。所以「锁屏看天气」实际走的是**下拉控制中心**，不是通知。早期版本用无障碍浮层强行盖上去，会挡住别人的通知还卡，已经整个删掉。
- **WorkManager 在 HyperOS 3 上不执行。** 任务躺在队列里（`state=0`），`run_attempt_count` 永远是 0，`cmd jobscheduler run -f` 强制跑也一样。真正干活的是前台服务里的 `Handler` 循环，WorkManager 只作为其他 ROM 上的兜底保留。
- **温度是画进图标里的，而且位置只有 96px。** HyperOS 控制中心磁贴只渲染图标、不渲染 label/subtitle，想在那里看到数字只能自己 `Canvas` 画字。用「涂满一块再量」的校准图实测（HyperOS 3 / Redmi Turbo 5）：

  | 事实 | 实测 |
  |---|---|
  | 图标可用区 | **96×96px**，居中在 220px 的磁贴圆圈里，四角完整不被裁 |
  | 画布尺寸 | 192 / 384 出来都是 96，调 bitmap density 也不放大 |
  | 非正方形位图 | **被强行压成正方形**（384×192 渲染成 96×96），不是等比缩放、也不是按宽度铺满 |
  | 颜色 | 纯红渲染成纯白——整张位图被染成单色 |
  | alpha | **保留**。128 的半透明白渲染成浅灰 |

  **能用的就这 96×96**，做不成宽卡片（要双格大磁贴得 MIUI 开口子，客户端决定不了）。
  也正因为这一格太小，**一格塞不下三样东西**：早先版本试过把当前温度、最高、最低
  挤在一起（圆弧 + 大号温度 + 两角高低温），高低温最多只能到 23px，一眼读不清，
  最后放弃了。现在天气拆成两个按钮：当前温度独占一格，高低温另起一格。

  **字号按字形紧边界（`getTextBounds`）算，不是 `fontMetrics`。** fontMetrics 给的是
  整行行距，其中一大截是留白；拿它当高度上限会把字号算小一大半——实测高低温只有
  24px 高，换紧边界后是 41px，当前温度是 61px。两个按钮都按**最宽的那种情况**
  统一收字号：零下 `-11` / `-15` 比两位数宽出一截，各算各的话会被边框裁掉半个字。
- **长按磁贴开 App 在 HyperOS 上不通。** `TileService` 没有 `onLongClick`；官方长按出口是 `QS_TILE_PREFERENCES` 广播，已经注册（`dumpsys package` 查得到），但 HyperOS 3 长按第三方磁贴直接弹系统「应用信息」，这条广播一次都不发。所以天气按钮只做「点一下刷新」，看预报请点通知栏那条或直接开 App。
- **控制中心按钮不能由 App 直接添加。** Android 13+ 只能 `requestAddTileService` 发起一次请求，弹不弹框看系统；Android 12 及以下必须手动编辑。
- **扫一扫深链会随微信/支付宝版本变化。** 微信走的是它自己的 `ShortCutDispatchAction` + `launchType` extra，支付宝走 `alipayqr://` scheme，都依赖 `AndroidManifest.xml` 里的 `<queries>` 声明。哪天不灵了，先去看这两家有没有改入口。

## 项目结构

```
app/src/main/kotlin/com/jack/lockdeck/
├── MainActivity.kt        设置页 + 天气速览（Compose，单文件偏长）
├── PickerActivity.kt      选择动作
├── action/                快捷动作定义、Intent 构造、统一执行出口
├── launch/                锁屏跳转透明中间页
├── data/                  定位、三个天气源、编解码、SharedPreferences 缓存
├── notify/                常驻通知、前台服务、刷新调度、锁屏可见性自检
├── tile/                  控制中心按钮
└── ui/theme/              Compose 主题（含 Material 3 模板自带的 Apache 头）
design/icon/               图标生成脚本
```

图标是脚本生成的：`design/icon/final_L.py` 产出 `res/` 里那三个 vector 与 SVG 源，`gen_legacy.py` 产旧式 webp。**改几何改脚本，别只改 XML**，否则设计稿和实际图标会分叉。PNG 是产物，不入库。

## 隐私

没有账号、没有统计、没有崩溃上报，不向作者或任何第三方回传数据。只有三类出网请求，都是功能本身：

- 天气源（小米 / 中央气象台 / Open-Meteo）
- 定位反查地名（BigDataCloud）
- 你点击按钮时跳转的目标 App

配置和天气快照存在本机 `SharedPreferences`（文件名 `lsw`）。`allowBackup` 是开着的，所以系统会把它并进你自己的账号备份（跟着换机走），**不经过作者**；想彻底不要，把 `AndroidManifest.xml` 里那个开关关掉即可。
